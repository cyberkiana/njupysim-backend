# NJUPTPhySim 头像与实验头图：存储、调用方案及 Nginx 配置规则

> 适用代码版本：NJUPTPhySim-master（后端 Spring Boot 3 + MyBatis，前端 Vue 3 + Vite + Element Plus）
> 相关配置文件：`nginx/nginx.conf`（开发期虚拟机版）、`deploy/nginx-server.conf`（生产单服务器版）、
> `src/main/resources/application.yml`、`deploy/application-prod.yml`

---

## 1. 方案总览

项目里有两类图片型静态资源，**采用了两套不同的存储与传输方案**：

| 对比项 | 用户头像 | 实验头图（封面） |
| --- | --- | --- |
| 存储位置 | **nginx 所在服务器**的 `/data/nginx/avatar/` | **后端服务器**本地目录 `./img`（可由 `resource.img-dir` 调整） |
| 上传通道 | 后端收到文件后，通过 **HTTP PUT（nginx WebDAV）** 推给 nginx 落盘 | 前端 multipart 直传后端，后端 `transferTo()` 写本地磁盘 |
| 读取通道 | **nginx 直接静态返回**，不经过后端 | **Spring Boot 静态资源映射**（`/img/**`）返回，经过后端 |
| 数据库字段 | `users.avatar`，存相对路径 `/avatar/{文件名}` | `resources.coverImage`，存相对路径 `/img/{文件名}` |
| 缓存策略 | nginx `expires 7d` + `Cache-Control: public` | 无专门缓存头（走后端默认响应头） |
| 上传大小限制 | nginx `client_max_body_size 5m` + 后端 multipart 5MB | 后端 multipart 5MB（未经过 nginx 时 nginx 限制不生效） |
| 主要代码 | `AvatarController` | `ResourcesController#uploadCover`、`WebMvcConfiguration` |

> WebGL 实验文件（`/webgl/**` → `./webgl-files`）与实验头图采用同一套方案，本文一并说明。

两套方案的设计取舍：
- **头像走 nginx**：头像读取频率高（每个页面都要显示），由 nginx 直接静态返回可以完全卸载后端压力，并利用 `expires 7d` 让浏览器缓存 7 天内的重复请求不发网络请求。
- **头图走后端**：头图属于实验管理功能，上传/读取频率低，直接复用 Spring Boot 的静态资源映射即可，少一次跨机部署依赖；代价是每次读取都占用后端 Tomcat 线程。

## 2. 用户头像：nginx 静态传输 + WebDAV 上传

### 2.1 存储位置与文件命名

- 落盘目录：nginx 服务器上的 `/data/nginx/avatar/`（对应 nginx 配置中两个 `alias` 指向的目录）。
- 文件名由后端生成：`{用户id}_{毫秒时间戳}.{扩展名}`，例如 `B22060101_1694567890.jpg`。
  - 带用户 id + 时间戳：避免不同用户上传重名覆盖，也防止越权覆盖他人文件。
  - 扩展名白名单：`jpg / jpeg / png / gif / webp / bmp`（`AvatarController.ALLOWED_EXTS`）。
- 数据库不存文件本体，只在 `users.avatar` 字段存相对 url：`/avatar/{文件名}`。

### 2.2 上传链路（写入）

```
浏览器                    vite/nginx(:80)              Spring Boot(:8081)            nginx WebDAV
   │  POST /api/common/user/avatar/upload     │                             │
   │  (multipart, 字段名 avatar)              │                             │
   ├─────────────────────────────────────────►│  去掉 /api 前缀转发          │
   │                                          ├────────────────────────────►│
   │                                          │  1. 扩展名白名单校验          │
   │                                          │  2. 生成文件名               │
   │                                          │  3. HttpClient 发起          │
   │                                          │     HTTP PUT 文件字节流      │
   │                                          ├─────────────────────────────┴──► dav_methods PUT
   │                                          │                                落盘 /data/nginx/avatar/
   │                                          │  4. 返回 2xx                   │
   │  ◄────────────  Result: "/avatar/xxx.jpg" ───────────────────────────────┤
   │                                                                          │
   │  POST /api/common/user/avatar/update                                     │
   │  { id, avatar: "/avatar/xxx.jpg" }   → 写入 users.avatar                 │
```

关键代码与配置：

| 环节 | 位置 | 说明 |
| --- | --- | --- |
| 前端发起 | `frontend/njuptpsim/src/api/user.js:31` | `POST /common/user/avatar/upload`，FormData 字段名 `avatar` |
| 后端接收与推送 | `AvatarController#upload` | 校验后用 `java.net.http.HttpClient` 向 `{avatar.nginx-base-url}{avatar.upload-path}{文件名}` 发 PUT，15s 超时；非 2xx 视为存储服务异常 |
| nginx 接收落盘 | `location /_avatar_upload/` | `dav_methods PUT`，写入 `alias` 指定的 `/data/nginx/avatar/` |
| 配置项 | `application.yml` 的 `avatar.*` | 开发：`nginx-base-url: http://192.168.233.130`；生产（`application-prod.yml`）：`http://127.0.0.1` |

注意：上传接口与"写库"是两步。`/upload` 只落盘并返回 url，前端拿到 url 后再调 `/update` 更新数据库（后端校验只能改自己的头像，见 `AvatarController#update`）。

### 2.3 读取链路（展示）

```
开发模式：
浏览器 <img src="/avatar/xxx.jpg">
   └─► vite dev server (proxy /avatar) ──► http://192.168.233.130/avatar/xxx.jpg
                                            └─► nginx location /avatar/ 静态返回

生产模式：
浏览器 <img src="/avatar/xxx.jpg">
   └─► nginx location /avatar/ ──► alias /data/nginx/avatar/xxx.jpg 直接返回
                                   （响应头 expires 7d, Cache-Control: public）
```

- 读取路径与后端**完全无关**：无论开发还是生产，头像文件的字节流都不经过 Spring Boot。
- 数据库存的是相对路径，前端 `<el-avatar :src="user.avatar">` 直接以相对路径请求，天然适配域名/端口变化。

### 2.4 安全规则

| 规则 | 实现位置 | 目的 |
| --- | --- | --- |
| 上传路径 IP 白名单 | `location /_avatar_upload/` 内 `allow` + `deny all` | 只有后端所在主机可以 PUT；公网无法直接写文件。开发环境 allow 宿主机 `192.168.233.1`，生产 allow `127.0.0.1` |
| 禁止目录列举 | `location /avatar/` 内 `autoindex off` | 不能浏览目录，只能按确切文件名访问 |
| 大小限制 | `client_max_body_size 5m` 与后端 `spring.servlet.multipart.max-file-size=5MB` 对齐 | 两端一致，避免"后端拒绝但 nginx 先收满"的浪费 |
| 文件名不可指定 | 文件名由后端按 用户id+时间戳 生成，客户端无法控制 | 防路径穿越与覆盖攻击 |

## 3. 实验头图：后端本地目录 + Spring Boot 静态映射

> 实验头图**不经过 nginx**，全程在后端进程内完成。WebGL 实验文件同理。

### 3.1 存储位置与文件命名

- 落盘目录：后端工作目录下的 `./img`（`application.yml` 中 `resource.img-dir`，可改为绝对路径）。
- 文件名由后端生成：`{yyyyMMddHHmmss}_cover.{扩展名}`，例如 `20250922143015_cover.png`。
  - 扩展名白名单：`png / jpg / jpeg / webp / gif`。
- 返回相对 url `/img/{文件名}`，由调用方写入 `resources.coverImage` 字段（注意该列名为驼峰，PO 里用 `@TableField("coverImage")` 显式映射）。

### 3.2 上传链路（写入）

```
管理员浏览器 ── POST /api/admin/res/upload-cover (multipart, 字段名 file) ──► Spring Boot
                                                                              ├─ 扩展名白名单校验
                                                                              ├─ Files.createDirectories(./img)
                                                                              ├─ file.transferTo(./img/{时间戳}_cover.{ext})
                                                                              └─ 返回 Result: "/img/xxx_cover.png"
管理员浏览器 ── POST /api/admin/res（新增）或 /api/admin/res/update（编辑） ──► coverImage 落库
```

前端调用点：`frontend/njuptpsim/src/views/root/exp/expView.vue`（管理员实验管理页，选择头图后立即上传，返回的 url 填入表单的 `coverImage`，随表单一起提交落库）。

### 3.3 读取链路（展示）

```
开发模式：
浏览器 <el-image src="/img/xxx_cover.png">
   └─► vite dev server (proxy /img) ──► http://localhost:8081/img/xxx_cover.png
                                         └─► Spring Boot 静态资源映射返回

生产模式（当前 nginx-server.conf 缺转发规则，见 §4.4）：
浏览器 <el-image src="/img/xxx_cover.png">
   └─► ??? 当前会命中 nginx location / 回退到 index.html —— 需补充 /img/、/webgl/ 转发
```

静态映射注册在 `WebMvcConfiguration#addResourceHandlers`：

```java
registry.addResourceHandler("/img/**")
        .addResourceLocations("file:" + Paths.get(imgUploadDir).toAbsolutePath().normalize() + "/");
registry.addResourceHandler("/webgl/**")
        .addResourceLocations("file:" + Paths.get(webglUploadDir).toAbsolutePath().normalize() + "/");
```

即 `GET /img/**`、`GET /webgl/**` 由 Spring MVC 直接从磁盘目录读文件返回，**不经过任何 Controller，也不消耗业务逻辑**，但仍占用 Tomcat 线程。

### 3.4 鉴权豁免

`WebMvcConfiguration#addInterceptors` 中两个拦截器均排除了这两类静态路径：

- `loginInterceptor`：`excludePathPatterns("/common/login", "/error", "/webgl/**", "/img/**")`
- `permitInterceptor`：`excludePathPatterns("/common/**", "/error", "/webgl/**", "/img/**")`

原因：`<img>` 标签与 WebGL 运行时发请求时不会携带 Authorization 头，若不豁免会导致图片 401 无法加载。IP 过滤器默认黑名单模式（`use-whitelist: false`，黑名单存数据库表 `sys_ip_blacklist`），未拉黑的 IP 正常放行。

## 4. Nginx 配置详细规则

### 4.1 两套配置的适用场景

| 文件 | 场景 | 拓扑 |
| --- | --- | --- |
| `nginx/nginx.conf` | 开发期"虚拟机版" | Windows 宿主机（192.168.233.1）跑后端 8081 + vite 前端；虚拟机（192.168.233.130）跑 nginx:80 + MySQL:3306 + Redis:6379 |
| `deploy/nginx-server.conf` | 部署期"单服务器版" | 前端 dist、后端 jar、MySQL、Redis、nginx 全在一台服务器，内部走 127.0.0.1，仅 80 对外 |

两者 location 规则一致，仅 `proxy_pass` 目标和上传白名单 IP 不同。

### 4.2 全局规则（http 块）

```nginx
include       /etc/nginx/mime.types;   # 按扩展名返回正确 Content-Type（jpg/png 等）
client_max_body_size 5m;               # 请求体上限 5MB，与后端 multipart 限制对齐，
                                       # 约束头像 PUT 与 /api 转发的上传体积
sendfile           on;                 # 静态文件零拷贝发送，提高 /avatar/ 大文件效率
keepalive_timeout  65;                 # 长连接保持 65s
```

### 4.3 location 规则逐条解析

**① `location /api/` —— 业务接口反向代理**

```nginx
location /api/ {
    proxy_pass http://192.168.233.1:8081/;   # 生产版为 http://127.0.0.1:8081/
    proxy_set_header Host $host;             # 保留原始域名
    proxy_set_header X-Real-IP $remote_addr; # 传真实客户端 IP（日志/封禁依赖）
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_connect_timeout 10s;               # 后端连接超时
    proxy_read_timeout    60s;               # 等后端响应超时（覆盖慢接口）
}
```

- `proxy_pass` 末尾带 `/`：转发时**去掉 `/api` 前缀**，`/api/common/login` → 后端 `/common/login`。与前端 axios `baseURL: '/api'`、vite 开发代理的 rewrite 规则三者对齐。
- 头像上传（multipart 最大 5MB）也走这条通道，因此 `client_max_body_size 5m` 必须全局生效。

**② `location /avatar/` —— 头像静态传输**

```nginx
location /avatar/ {
    alias /data/nginx/avatar/;    # URL 前缀替换：/avatar/a.jpg → /data/nginx/avatar/a.jpg
    expires 7d;                   # 响应头 Expires/Cache-Control max-age=7天，浏览器强缓存
    add_header Cache-Control "public";
    autoindex off;                # 禁止目录列举，仅允许按确切文件名访问
}
```

- 用 `alias` 而非 `root`：`alias` 会把 location 匹配的前缀整体替换掉；若写 `root /data/nginx/avatar`，实际路径会变成 `/data/nginx/avatar/avatar/a.jpg`，是常见错误。
- 7 天强缓存的前提是文件名含时间戳——内容永远不变、只新增文件，所以可以放心长缓存；更新头像 = 新文件名 + 新 url 落库，旧缓存天然失效。

**③ `location /_avatar_upload/` —— 头像上传（WebDAV）**

```nginx
location /_avatar_upload/ {
    alias /data/nginx/avatar/;    # 与 /avatar/ 指向同一目录：上传即生效可访问
    dav_methods PUT;              # 只开放 PUT 方法（nginx 需编译 ngx_http_dav_module，默认含）
    allow 192.168.233.1;          # 开发版：仅宿主机后端可写；生产版：allow 127.0.0.1;
    deny all;                     # 其余来源一律 403
}
```

- 这是"后端有写权限、公网只读"的关键：外部即使知道路径，PUT 也会被 `deny all` 拒绝。
- `alias` 与 `/avatar/` 指向同一目录，因此后端 PUT 成功后，`/avatar/{文件名}` 立即可读，无同步步骤。

**④ `location /` —— 前端静态页面（仅生产版启用）**

```nginx
location / {
    root /data/nginx/web/dist;
    index index.html;
    try_files $uri $uri/ /index.html;   # vue-router history 模式：未命中文件回退 index.html
}
```

- 开发版中此段被注释（前端由 vite dev server 提供）。
- `try_files` 的回退行为是 §4.4 问题成因：任何 dist 里不存在的路径（包括 `/img/...`）都会返回 index.html 的内容。

**匹配优先级**：nginx 前缀匹配中，`/api/`、`/avatar/`、`/_avatar_upload/` 都是更长的前缀，优先于 `/`，因此它们不会被兜底的 `location /` 抢走。

### 4.4 生产部署注意事项与已知缺口

**已知缺口：生产版 nginx 未转发 `/img/` 与 `/webgl/`。**

实验头图与 WebGL 文件由后端静态映射提供，但数据库存的是绝对路径形式的相对 url（`/img/xxx`、`/webgl/xxx`）。生产环境浏览器会直接向 nginx 80 端口请求这些路径，当前会命中 `location /` 并回退到 `index.html`，导致**头图裂图、WebGL 实验加载失败**。需在 `deploy/nginx-server.conf` 的 server 块中补充：

```nginx
# 实验头图与WebGL文件：转发给后端静态资源映射（/img/**、/webgl/** 由 Spring Boot 直出）
location /img/ {
    proxy_pass http://127.0.0.1:8081;
    proxy_set_header Host $host;
    expires 7d;
    add_header Cache-Control "public";
}
location /webgl/ {
    proxy_pass http://127.0.0.1:8081;
    proxy_set_header Host $host;
}
```

> 备选方案：不转发，改用 nginx 直接静态服务——把后端 `resource.img-dir`、`webgl.upload-dir` 配置为 nginx 可读目录（如 `/data/nginx/img`），用 `alias` 暴露。优点是图片读取卸载后端，缺点是上传后目录需两边一致、权限要打通，当前规模下用 proxy 更简单。

**其他部署核对项**：

| 检查项 | 要求 |
| --- | --- |
| 目录创建 | `mkdir -p /data/nginx/avatar /data/nginx/web/dist`，属主给 nginx 运行用户（`user nginx;`）可写 avatar 目录 |
| dav 模块 | 确认 nginx 编译含 `ngx_http_dav_module`（`nginx -V` 查看；发行版包通常自带） |
| 白名单 IP | 开发版 `allow 192.168.233.1`、生产版 `allow 127.0.0.1` 必须与后端实际出口 IP 一致，否则后端 PUT 被 403 |
| 后端生产配置 | `deploy/application-prod.yml` 中 `avatar.nginx-base-url: http://127.0.0.1`（同机）；若后端与 nginx 分机则改成 nginx 的内网 IP，并把该 IP 加入 `_avatar_upload` 的 allow |
| 上传大小 | nginx `client_max_body_size` ≥ 后端 `spring.servlet.multipart.max-file-size`（当前均为 5MB） |
| 防火墙 | 8081 端口不对公网开放（头像上传白名单依赖"写入口只有 nginx"这一前提） |
| 配置生效 | `nginx -t` 校验后 `systemctl reload nginx` |

### 4.5 开发/生产环境全链路对照

| 动作 | 开发环境（虚拟机版） | 生产环境（单服务器） |
| --- | --- | --- |
| 头像上传 | vite(`/api`) → 宿主机 8081 → PUT → 虚拟机 nginx `:80/_avatar_upload/` | nginx(`/api`) → 本机 8081 → PUT → 本机 nginx `:80/_avatar_upload/` |
| 头像读取 | vite(`/avatar`) → 虚拟机 nginx 静态返回 | 浏览器 → nginx `/avatar/` 静态返回 |
| 头图上传 | vite(`/api`) → 宿主机 8081 → 写宿主机 `./img` | nginx(`/api`) → 本机 8081 → 写本机 `./img` |
| 头图读取 | vite(`/img`) → 宿主机 8081 静态映射返回 | 浏览器 → nginx →（**需补充** `/img/` 转发）→ 本机 8081 |
| WebGL 加载 | vite(`/webgl`) → 宿主机 8081 静态映射返回 | 浏览器 → nginx →（**需补充** `/webgl/` 转发）→ 本机 8081 |

## 5. 常见问题排查

| 现象 | 可能原因 | 排查入口 |
| --- | --- | --- |
| 上传头像报"无法连接头像存储服务" | nginx 未启动 / `avatar.nginx-base-url` 不通 / 防火墙拦截 | 后端日志 `AvatarController`；`curl -X PUT` 手动测试 |
| 上传报 HTTP 403 | 后端出口 IP 不在 `/_avatar_upload/` 的 allow 列表 | nginx 配置 allow/deny；`error.log` 中 `access forbidden by rule` |
| 头像 url 正确但 404 | 文件未落盘（PUT 失败但前端仍拿到 2xx？不会——PUT 非 2xx 后端会报错）；或 `alias` 路径写错 | `ls /data/nginx/avatar/`；`GET /avatar/` 精确文件名 |
| 头像改了但显示旧图 | 7 天强缓存期内复用了同名文件（不应发生，文件名含时间戳）；或浏览器本地缓存 | 强刷（Ctrl+F5）；核对落库 url 是否为新文件名 |
| 生产环境头图裂图 / WebGL 白屏 | nginx 缺 `/img/`、`/webgl/` 转发，请求被回退成 index.html | 浏览器 Network 看该请求响应是否为 HTML；按 §4.4 补配置 |
| 上传大图被拒 | 超过 5MB：nginx 层报 413，后端层报 multipart 异常 | 压缩图片或调大两端限制（需同步） |
